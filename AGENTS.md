# AGENTS.md

Guide for coding agents working on this repo. Humans: see README.md.

## Rules

- Lowest possible resource use. No polling loops, no resident helpers, no runtimes in `blackout.exe`. Helpers run once and exit.
  The one periodic tick is the 4 s iCUE LINK timer (lighting keep-alive and, owner-approved 11 Nov 2026, the coolant fan curve).
- Win32 C only in `src/`. No new dependencies beyond system DLLs.
- Docs: plain, short, no filler. Never use em dashes or en dashes in any file.
- Every feature must be optional and skip silently when its hardware or config is missing.
- Never write to the RAM SMBus directly. RAM goes through the FURY module only.

## Architecture

One hidden window. Everything is driven by `GUID_CONSOLE_DISPLAY_STATE` (`WM_POWERBROADCAST`), which Windows sends on registration and on every display on/off, including the idle timeout.

- **Display off (0):** save window placements, DDC power off listed monitors, `setRgb(off)`, apply fan "screens off" duty.
- **Display on (1):** DDC power on, restore windows after 4 s (and 2.5 s after each `WM_DISPLAYCHANGE`), `setRgb(on)`, fan "screens on" duty.
- **Dimmed (2):** ignored.
- **Screens off click:** set AC video idle timeout to 1 s via powrprof, restore it on the next display-off event. Fallback after 6 s: `SC_MONITORPOWER`. The fallback leaves some iGPU DisplayPort outputs half awake, which makes monitors flash "No Signal"; that is what `[ddc]` fixes.
- **`setRgb`:** writes `RgbOn`, refreshes the LINK hub, spawns OpenRGB and furyled. Changes during a 6 s busy window are queued; last one wins.

State lives in `HKCU\Software\Blackout` (DWORDs): `RgbOn`, `Sync`, `FanCtl`, `FanAwake`, `FanSleep` (0 = same as awake). Curve state: `FanCurve` (1 = follow coolant), `RgbWant`, `HotkeyMode`, `WakeClick`, `WakeEsc`, the panel's overrides `Curve` (REG_SZ), `FanMax`, `Hysteresis`, and status it writes: `Coolant` (C x10, averaged), `FanDuty` (%, 0 = BIOS). Config lives in `blackout.ini` beside the exe (`[rgb]`, `[link]`, `[ddc]`, `[fans]`).

- **Coolant fan curve:** each 4 s tick reads the LINK coolant sensor, averages it (alpha 0.13, about 30 s) and writes the curve duty to the `[fans]` channels. Up at once, down only to curve(t + hysteresis). 5 failed reads in a row, exit, `WM_ENDSESSION` and `PBT_APMSUSPEND` restore the saved BIOS mode and duty. After resume the chip is BIOS-controlled again and the next tick takes over afresh.
- **Panel** (`src/panel.c`): right-click opens a popup (`BlackoutPanel`, WS_POPUP, CS_DBLCLKS, frame extended into the client; DWM attributes 3 transitions off, 20 dark, 33 = 1 no rounding, 34 border none, 38 = 3 acrylic; 13 cloak until the first frame is drawn, so it appears and closes instantly). Docked flush to the work area's right edge and the taskbar; a window region rounds only the corner facing the desktop. Closes on deactivate or Esc. A tray click within 300 ms of closing does not reopen it. Falls back to the plain menu if Direct2D fails.
  - **Rendering is on the CPU**: an `ID2D1DCRenderTarget` (software, premultiplied alpha) bound to the window DC each frame. Measured with `--panel-bench`: about 15 ms to open and about 15 MB while open, against about 90 to 400 ms and 60 to 70 MB for a GPU `HwndRenderTarget`, which loads the graphics driver into the process. d2d1.dll and dwrite.dll are loaded on open and freed on close; about 5 MB of commit and 36 handles stay behind after the first open (working set returns to under 1 MB). Do not switch back to a GPU target.
  - **Views:** Main, and Settings with tabs Fans, Wake, System. Every Settings tab is `SET_H` high so the tabs never move under the cursor; the window only resizes between Main and Settings when their heights differ. The Fans tab is hidden when no `[fans]` is configured (`fanWhy` 1); a configured but broken fan curve shows a notice on Main and the reason on the tab.
  - **Layout grid:** 16 outer padding, 14 inside cards, 12 between blocks, 18 between sections, 44 rows. Colours come from `ink()`, `dim()`, `tone()`, `warn()`, `knob()`, so both themes work (`SystemUsesLightTheme`).
  - **Fans tab:** points drag within their neighbours and 20..`max`; double-click on the chart adds a point (up to `MAX_CURVE`), right-click removes one (two always stay). On release the curve goes to `HKCU\Software\Blackout\Curve` (REG_SZ) and is applied at once. Steppers write `FanMax` and `Hysteresis`. All three override the ini; Reset deletes them.
  - **System tab:** status rows from `fanWhy`, `coolant`, `linkOk`, `hasOpenRgb`, `hasRam`, `ddcIds`, `isElevated()`.
  - RPM is read only while the panel is open. History: 225 coolant samples (15 min, C x100).
- **RGB intent:** `RgbWant` is what the user wants while the screens are on (the panel switch); `RgbOn` is the state right now. With `Sync`, screens off sends off and screens on sends `RgbWant`, so a manual off survives a wake.
- **Wake log:** while the screens are off, raw input (mouse and keyboard, `RIDEV_INPUTSINK`) is registered and `WM_INPUT` stores only the device handle and tick. When the screens come on, `wakeRecord()` names the cause: Hotkey mode input, the device's HID product string (with "(not blocked)" if Hotkey mode was armed), or "No input seen". Memory only, five entries. Unregistered while the screens are on.
- **Tick cost:** the 4 s tick does 9 HID transfers with one reused event handle, no registry reads (`litOn`, `curveOn` are cached), and writes `Coolant` only when the value changes. The tray tooltip is rewritten only when the whole-degree reading or the duty changes. Measured: about 0.2 ms of CPU per tick (1.1 s over 5.4 h), 1 thread.
- **Hotkey mode:** on display off (state 0) and `HotkeyMode` = 1, a thread installs WH_KEYBOARD_LL and WH_MOUSE_LL hooks that swallow all non-injected input. Left button down (`WakeClick`) or Esc down (`WakeEsc`) posts `WM_WAKE`: the thread quits (unhooks) and Blackout injects a 1 px mouse nudge plus `ES_DISPLAY_REQUIRED`. Display on (state 1) or exit also unhooks. The panel keeps at least one wake input on. Hooks run on their own thread so the 4 s LINK tick can't stall input past LowLevelHooksTimeout. Untested assumption to verify on hardware: swallowed input does not wake the display.
- **Developer modes** (no hardware access, no single-instance lock, every switch faked; see the end of `panel.c`): `--panel-test [flags]` opens the panel with preview data; `--panel-shot [flags] out=<file.bmp>` draws one view off-screen with no window at all; `--panel-bench [gpu]` opens and closes it five times while cloaked and logs time, memory and handles to `%TEMP%\blackout-bench.txt`. `tools/panel_shots.py <exe> <dir>` renders every state plus a contact sheet for design review, and with `--readme` the `docs/panel-*.png` images. Review the sheet after any panel change.
- **Elevation:** fan control needs admin. Elevated, **Start with Windows** makes a logon task `Blackout` (highest privileges, no time limit) instead of the Run key. A Run-key instance started first holds the single-instance mutex, so never have both. `ChangeWindowMessageFilterEx` lets `WM_COMMAND`, the tray callback and `TaskbarCreated` reach the elevated window.

## Device protocols

**Corsair Commander Pro** (VID 1B1C, PID 0C10). 65-byte output report `[0, 0x23, channel 0..5, duty%]`. Write only. Resets to its default after power loss, so duty is re-applied on every display event.

**Corsair iCUE LINK System Hub** (VID 1B1C, PID 0C3F, interface MI_00). 513-byte output reports `[0, 0, 1, cmd..., data...]`, each answered by one 513-byte input report (overlapped I/O, 1 s timeouts). Colour sequence:

1. Software mode `01 03 00 02`
2. Close endpoint `05 01 01` + `22`
3. Open colour endpoint `0d 00` + `22`
4. Write colour `06 00` + `[len lo, len hi, 0, 0, 12, 00, RGB x leds]`, len = leds * 3 + 2
5. Close endpoint `05 01 01` + `22`

The hub falls back to its stored hardware lighting about 5 s after the last frame, so the frame is re-sent every 4 s (30 s back-off on failure). On exit Blackout sends hardware mode `01 03 00 01`. Speeds: endpoint `17`, data type `25 00`.

**iCUE LINK coolant sensor** (from FanControl.CorsairLink). Close `05 01 01` + `21`, open `0d 01` + `21`, read `08 01`, close. Reply (report ID at [0]): [4] status, [5..6] data type `10 00`, [7] sensor count, then 3 bytes per sensor: status (0 = present), int16 LE C x10.

**Nuvoton NCT679x Super I/O** (chip ID high byte D4 or D8) through PawnIO `LpcIO.bin`, holding the `Global\Access_ISABUS.HTP.Method` mutex. Config mode: write `87 87` to 2E (or 4E), LDN `0B`, HWM base at 60/61, clear the I/O space lock (reg 28 bit 4), `ioctl_find_bars`, exit with `AA`. HWM index/data at base+5/base+6, bank select register `4E`. Per channel page `100 200 300 800 900 A00 B00`: mode at page+02 (bits 7..4, 0 = manual), duty at page+09 (0..255). RPM at `4C0 + 2 * ch` (16-bit). Same map as Linux nct6775 and LibreHardwareMonitor.

**DDC/CI.** VCP `0xD6`: 1 = on, 5 = off. Monitors matched by hardware ID from `EnumDisplayDevices(szDevice).DeviceID`. A monitor powered off this way stays enumerated, so it can be woken over DDC.

**Kingston FURY (module).** Kingston's `FURYController_Service` (Windows service, auto start) hosts a WebSocket at `ws://127.0.0.1:55599/`. Every message is base64 of `salt(32) | iv(32) | ciphertext`, Rijndael with 256-bit block, CBC, PKCS7, key = PBKDF2-SHA1(passphrase `3m23s45i599`, salt, 1000 iterations, 32 bytes). Requests are JSON:

- `{"root":{"api":"set_keep_status","keep":"1"}}` makes the service re-apply the last effect after resume.
- `{"root":{"api":"set_dram_led","ctrl_settings_ddr5":{"slot_0":{...},"slot_1":{...}}}}` with `mode` `static_color`, `ctrl_mode` `ctrl_color`, `brightness` 0 to 100, `color_table` `[[r,g,b]]`. Reply `"status":"0"` means applied.

Field list is in `modules/fury/furyled.cs`. The service also logs to `C:\Program Files (x86)\Kingston Fury\FuryCTRL_SDK\Log`.

## Verifying on a real machine

- Panel: `tools/panel_shots.py` (off-screen, safe at any time). The real panel opens remotely by posting `WM_APP + 1` with lParam `WM_CONTEXTMENU` (0x7B) to the `Blackout` window; posting again closes it. To find its window from a WSL-launched shell use EnumWindows by process ID (FindWindow fails there).
- Updating the elevated instance without UAC: post `WM_COMMAND` 5 (Exit) to the `Blackout` window, replace the exe, `schtasks /Run /TN Blackout`.
- Coolant curve: `Coolant` and `FanDuty` in `HKCU\Software\Blackout`; `sioprobe.exe LpcIO.bin` (admin) shows mode 0 and the duty on the curve channels.
- Fans: `liquidctl --match "Commander Pro" status` shows RPM per channel.
- OpenRGB: each run writes `%APPDATA%\OpenRGB\logs\OpenRGB_*.log`. Look for `Registering RGB controller` and errors.
- FURY: `furyled off` prints the reply and exits 0 on success.
- Display cycle without touching the PC: send `SC_MONITORPOWER` 2 from a window, wait, then `mouse_event` to wake.

## Known pitfalls

- OpenRGB 1.1 fails to detect some Kingston FURY DDR5 kits even with admin and PawnIO. Its probing also interrupts the RAM effect. Disable its DRAM detectors when using the FURY module.
- A missing device in an OpenRGB `-d` list makes the whole CLI call fail (exit -1). Keep `off`/`on` to devices that are always present.
- Corsair channels with zone size 0 ignore Static colours.
- OpenRGB releases the iCUE LINK hub to hardware mode on exit, which fights the keep-alive. Disable its LINK detector.
